# 도구 선정 — Lumin 광고

각 단계별 주 도구(Primary) + 대체 도구(Backup)를 지정하고, 선정 이유를 남긴다.
(요구사항: 이미지/비디오/오디오 각 1종 이상 사용, 대체 도구 준비)

## 1. 이미지 생성
- **Primary: Gemini (Imagen 3 기반 이미지 생성)**
  - 이유: 회사 팀 계정으로 이미 확보되어 있어 크레딧/접근성 문제가 가장 적음. 하나의 대화(채팅) 안에서 연속적으로 이미지를 생성·수정할 수 있어 스타일 일관성 관리가 용이함.
- **Backup: Midjourney 또는 Adobe Firefly**
  - 이유: Gemini 쪽 사용량 제한(팀 계정 쿼터, 동시 접속 제한 등)에 걸릴 경우 대체. Midjourney는 시네마틱 톤 표현에, Firefly는 저작권 안전성 측면에서 대체 우선순위로 둠.

## 2. 비디오 생성(이미지→영상 변환)
- **Primary: Kling AI (무료 플랜)** — *(당초 Veo 예정 → 실제 제작 중 전환, 아래 "도구 전환 기록" 참고)*
  - 이유: 일일 무료 크레딧이 매일 리셋되어 5씬 작업에 크레딧 걱정이 적음, 최대 10초 클립 지원(우리 씬 대부분에 부합), 인물/표정 표현에 강점이 있어 인물이 등장하는 씬(1, 4)에도 안전.
- **Backup: Luma Dream Machine / Pika / Runway**
  - 이유: Kling 크레딧 소진 또는 접속 이슈 시 대체. Luma는 월 30회(5초 클립), Pika는 월 80회(3초 클립, 상업적 사용 허용), Runway는 1회성 125크레딧(약 6초).
- **원래 계획: Gemini (Veo)** — 접근 장애로 실사용에서 제외 (아래 참고)
  - 참고: Veo는 프롬프트에 따라 네이티브 오디오(주변음)까지 함께 생성 가능한 기능이 있었으나, 실사용에서 도달하지 못함.

### 도구 전환 기록 (Veo → Kling)
- **시도한 것**: Gemini(Veo)에 씬1 이미지+프롬프트로 영상 생성 요청 → "I can't generate that video" 오류
- **1차 진단**: 인물 묘사에 대한 콘텐츠 정책 제한으로 추정 → 인물을 제거하고 "사람이 방금 있었던 흔적"만 남기는 프롬프트로 이미지를 다시 생성 후 재시도
- **결과**: 사람을 완전히 제외한 프롬프트로도 동일한 오류 재발 → 콘텐츠 정책이 아니라 **팀 계정에 Veo 영상 생성 크레딧/권한 자체가 없는데 UI는 사용 가능한 것처럼 노출되는 문제**로 재진단
- **결정**: 시간 낭비를 막기 위해 Veo 재시도를 중단하고, 무료 크레딧이 확실히 보장되는 Kling AI로 비디오 생성 도구를 전환
- **배운 점**: 동일 오류가 프롬프트를 바꿔도 반복되면 "콘텐츠 문제"가 아니라 "계정/권한 문제"일 가능성을 먼저 의심하고, 대체 도구로 빠르게 피벗하는 것이 크레딧/시간 관리에 효율적임 (제약사항 4 "도구 접근성 대응"의 실제 적용 사례)

## 3. 오디오 생성
### 3-1. 배경음악(BGM)
- **Primary: Suno**
  - 이유: 로파이/잔잔한 피아노-신스 패드 프롬프트에 강하고, 씬별이 아닌 전체 트랙 1개로 뽑아 톤을 통일하기 쉬움(오디오 톤 미스매치 방지). Gemini는 이미지/영상 전용으로 쓰고 오디오는 전문 도구로 분리.
- **Backup: Udio**
  - 이유: Suno 크레딧 소진 시 대체. 분위기 묘사 프롬프트 호환성 유사.

### 3-2. 내레이션(TTS)
- **Primary: ElevenLabs**
  - 이유: 한국어 음성 자연스러움과 감정 톤(차분함) 조절이 우수, 보이스 하나를 전 씬에 고정해 일관성 유지.
- **Backup: Typecast**
  - 이유: 국내 서비스로 한국어 억양이 더 자연스러운 보이스 옵션 보유, ElevenLabs 대기/쿼터 이슈 시 전환.

### 3-3. 비디오 생성 도구의 네이티브 오디오 처리 방침
- 영상 생성 도구(Kling 등)가 자체적으로 소리를 생성/포함하는 경우, 이는 "선택적 참고 트랙"으로만 활용
- **BGM과 내레이션은 반드시 Suno/ElevenLabs로 별도 생성 후 편집 단계에서 믹싱** → 브랜드 사운드 톤(로파이/차분함)을 일관되게 통제하기 위함
- 영상 자체에 오디오가 포함되어 있어도 최종 믹싱에서 볼륨을 낮추거나 제거하고, 별도 생성한 BGM/내레이션을 메인으로 사용

## 일관성(스타일) 유지 전략
- **인물 미노출/실루엣 전략**: 얼굴 클로즈업을 최소화(씬 구성 참고)하여 씬마다 인물 얼굴이 달라지는 AI 특유의 문제를 원천 회피
- **단일 대화(chat) 내 연속 생성**: Gemini는 Midjourney의 `--sref` 같은 명시적 스타일 코드가 없으므로, 하나의 대화 세션 안에서 이전 씬 이미지를 참고 이미지로 첨부하며 순차적으로 생성 → 모델이 맥락을 유지하도록 유도
- **고정 스타일 키워드 반복**: 모든 프롬프트에 동일한 수식어 세트를 반복 사용
  `warm amber tone, cinematic lighting, 35mm lens, shallow depth of field, minimal Korean apartment interior`
- **이미지→영상 파이프라인 고정**: 비디오 생성 도구(Kling)에 순수 텍스트 프롬프트가 아니라 "Gemini로 확정한 키비주얼 이미지"를 입력으로 사용해 영상 단계에서 스타일이 이탈하지 않도록 함
- **BGM 단일 트랙 원칙**: 씬별로 따로 생성하지 않고 44초 분량 1개 트랙을 생성 후 편집 단계에서 볼륨만 조정 → 오디오 톤 미스매치 방지

## 크레딧/대기열 이슈 대응 (제약사항 반영)
1. 이미지 생성 단계에서 5씬 전체 키비주얼을 먼저 확정 (재생성 최소화)
2. 확정된 이미지만 비디오 변환 단계로 진행 (영상 생성 크레딧 절약)
3. Primary 도구(이미지: Gemini / 영상: Kling)가 쿼터·접근 문제 시 즉시 Backup 도구로 전환, 고정 스타일 키워드는 동일하게 유지해 톤 차이 최소화
4. **실제 사례**: 영상 생성 도구가 Gemini(Veo) → Kling으로 전환됨 (위 "도구 전환 기록" 참고)

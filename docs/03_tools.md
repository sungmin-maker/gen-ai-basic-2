# 도구 선정 — Lumin 광고

각 단계별 주 도구(Primary) + 대체 도구(Backup)를 지정하고, 선정 이유를 남긴다.
(요구사항: 이미지/비디오/오디오 각 1종 이상 사용, 대체 도구 준비)

## 1. 이미지 생성
- **Primary: Gemini (Imagen 3 기반 이미지 생성)**
  - 이유: 회사 팀 계정으로 이미 확보되어 있어 크레딧/접근성 문제가 가장 적음. 하나의 대화(채팅) 안에서 연속적으로 이미지를 생성·수정할 수 있어 스타일 일관성 관리가 용이함.
- **Backup: Midjourney 또는 Adobe Firefly**
  - 이유: Gemini 쪽 사용량 제한(팀 계정 쿼터, 동시 접속 제한 등)에 걸릴 경우 대체. Midjourney는 시네마틱 톤 표현에, Firefly는 저작권 안전성 측면에서 대체 우선순위로 둠.

## 2. 비디오 생성(텍스트→영상, Text-to-Video)
- **Primary: Gemini (Veo)** — *(아래 "트러블슈팅 기록" 참고: 이미지 참고 없이 순수 텍스트 프롬프트로 정상 작동 확인)*
  - 이유: 이미지 생성과 동일 계정/생태계, 별도 가입 불필요. 단, **참고 이미지를 첨부하는 이미지→영상 방식은 막히고, 텍스트만 입력하는 방식은 정상 작동**하는 것으로 확인됨 → 파이프라인을 텍스트-투-비디오 방식으로 확정.
  - 제약: 클립당 **최대 8초**(4/6/8초 중 선택, Veo 3 모델 공통 제한) → 씬 길이 설계에 반영(아래 "클립 길이 제한 반영" 참고).
- **Backup: Kling AI (무료 플랜)**
  - 이유: Gemini/Veo 쿼터·대기열 문제 재발 시 대체. 일일 무료 크레딧 리셋, 최대 10초 클립, 인물 표현에 강점.
- **2차 Backup: Luma Dream Machine / Pika / Runway**
  - 이유: Kling도 막힐 경우 최종 대안. Luma는 월 30회(5초), Pika는 월 80회(3초, 상업적 사용 허용), Runway는 1회성 125크레딧(~6초).

### 트러블슈팅 기록 (Veo 영상 생성 오류 해결)
- **1차 증상**: Gemini(Veo)에 씬1 **이미지를 참고로 첨부**하고 프롬프트를 넣어 영상 생성 요청 → "I can't generate that video" 오류
- **1차 진단(추정)**: 인물 묘사에 대한 콘텐츠 정책 제한으로 추정 → 인물을 제거하고 "사람이 방금 있었던 흔적"만 남기는 프롬프트로 이미지를 다시 생성 후 재시도했으나 동일 오류 재발
- **2차 진단(추정)**: 콘텐츠 정책이 아니라 팀 계정의 Veo 접근 권한/크레딧 문제로 재추정 → Kling AI로 잠정 전환
- **실제 원인 확인**: 참고 이미지를 첨부하지 않고 **텍스트 프롬프트만으로** 재시도한 결과 정상 작동 확인. 즉, 오류의 실제 원인은 "**이미지 참조(image-to-video) 입력에 대한 제한**"이었고, 텍스트-투-비디오는 처음부터 문제없었음
- **최종 결정**: Gemini(Veo)를 텍스트-투-비디오 방식으로 그대로 사용. 다만 이미지를 영상 생성에 직접 입력할 수 없으므로, 일관성 전략을 "이미지 입력 기반"에서 "**동일한 상세 텍스트 프롬프트를 이미지·영상 양쪽에 반복 사용**"하는 방식으로 조정 (아래 일관성 전략 참고)
- **배운 점**: 같은 오류가 반복될 때 원인을 하나로 단정하지 말고, "입력 방식(이미지 첨부 여부)"처럼 변수를 하나씩 분리해서 재현 테스트하는 것이 정확한 원인 파악에 효과적임. 이번 사례는 콘텐츠 정책도, 계정 권한 문제도 아닌 "입력 모달리티(이미지 대 텍스트)" 문제였음

## 3. 오디오 생성
### 3-1. 배경음악(BGM)
- **실제 사용: Gemini** *(당초 Suno 계획 → 전환, 정확한 기능/모델명 확인 중)*
  - 전환 사유: Suno 무료 계정은 생성된 트랙 다운로드가 불가능해 실사용 불가로 판단, Gemini 생태계 내 기능으로 대체
- **원래 계획: Suno**
  - 이유(계획 당시): 로파이/잔잔한 피아노-신스 패드 프롬프트에 강하고, 씬별이 아닌 전체 트랙 1개로 뽑아 톤을 통일하기 쉬움(오디오 톤 미스매치 방지)
  - 무료 플랜 제약: 다운로드 불가 → 실제 제작에서는 배제
- **Backup: Udio**
  - 이유: Gemini 오디오 생성이 막힐 경우 대체. 다만 Udio도 무료 플랜 다운로드 정책을 사전 확인 필요.

### 3-2. 내레이션(TTS)
- **Primary: ElevenLabs**
  - 이유: 한국어 음성 자연스러움과 감정 톤(차분함) 조절이 우수, 보이스 하나를 전 씬에 고정해 일관성 유지.
- **Backup: Typecast**
  - 이유: 국내 서비스로 한국어 억양이 더 자연스러운 보이스 옵션 보유, ElevenLabs 대기/쿼터 이슈 시 전환.

### 3-3. Veo 네이티브 오디오 처리 방침
- Veo가 생성하는 주변음(예: 옷 스치는 소리, 미세한 실내 소음)은 "선택적 참고 트랙"으로만 활용
- **BGM과 내레이션은 반드시 별도 도구(BGM: Gemini / 내레이션: ElevenLabs)로 생성 후 편집 단계에서 믹싱** → 브랜드 사운드 톤(로파이/차분함)을 일관되게 통제하기 위함
- Veo 생성 시 오디오 옵션은 가급적 끄거나, 켜지더라도 최종 믹싱에서 볼륨을 낮춰 배경 질감 정도로만 사용

## 일관성(스타일) 유지 전략
- **인물 미노출/실루엣 전략**: 얼굴 클로즈업을 최소화(씬 구성 참고)하여 씬마다 인물 얼굴이 달라지는 AI 특유의 문제를 원천 회피
- **단일 대화(chat) 내 연속 생성 (이미지)**: Gemini는 Midjourney의 `--sref` 같은 명시적 스타일 코드가 없으므로, 하나의 대화 세션 안에서 이전 씬 이미지를 참고 이미지로 첨부하며 순차적으로 생성 → 모델이 맥락을 유지하도록 유도
- **고정 스타일 키워드 반복 (이미지+영상 공통)**: 모든 프롬프트(이미지용, 영상용 모두)에 동일한 수식어 세트를 반복 사용
  `warm amber tone, cinematic lighting, 35mm lens, shallow depth of field, minimal Korean apartment interior`
- **"동일 상세 프롬프트" 방식 (이미지→영상 대신)**: Veo가 이미지를 입력으로 받지 못하므로(위 트러블슈팅 기록 참고), 영상 프롬프트 자체에 이미지 프롬프트의 구도·색감 묘사를 거의 그대로 포함시켜 텍스트만으로 동일한 장면이 재현되도록 함 → 이미지와 영상이 완전히 동일하지는 않지만, 동일한 서술로 최대한 근접한 톤을 확보
- **클립 길이 제한 반영**: Veo는 클립당 최대 8초(4/6/8초 중 선택)만 지원 → 10초 이상으로 설계된 씬(3, 4)은 8초로 축소 조정 (`docs/02_scene_structure.md`, `docs/04_prompts.md` 참고)
- **BGM 단일 트랙 원칙**: 씬별로 따로 생성하지 않고 전체 분량 1개 트랙을 생성 후 편집 단계에서 볼륨만 조정 → 오디오 톤 미스매치 방지

## 크레딧/대기열 이슈 대응 (제약사항 반영)
1. 이미지 생성 단계에서 5씬 전체 키비주얼을 먼저 확정 (재생성 최소화, 영상 프롬프트 작성 시 참고용으로 활용)
2. 영상은 이미지 입력 없이 텍스트 프롬프트만으로 별도 생성 (Veo 제약 반영)
3. Primary 도구(이미지: Gemini/Imagen / 영상: Gemini/Veo)가 쿼터·접근 문제 시 즉시 Backup 도구(Kling 등)로 전환, 고정 스타일 키워드는 동일하게 유지해 톤 차이 최소화
4. **실제 사례**: 영상 생성 오류를 "이미지 참고 첨부 시에만 발생"으로 정확히 진단, 텍스트-투-비디오 방식으로 Gemini(Veo)를 계속 사용하기로 확정 (위 "트러블슈팅 기록" 참고)
